# OctoAcme Project Management Documentation

## Welcome to OctoAcme Project Management

This directory contains the complete guide to how OctoAcme runs projects. Whether you're starting a new initiative, planning a release, or improving team processes, you'll find the guidance you need here.

## Project Lifecycle at OctoAcme

Our project management approach follows five key phases:

1. **Initiation** — Validate business need, identify stakeholders, define success metrics
2. **Planning** — Break work into shippable increments, identify dependencies and risks
3. **Execution** — Build, test, review, and iterate with regular standups and demos
4. **Release** — Deploy to production with proper verification and rollback planning
5. **Retrospective** — Capture learnings and convert them into continuous improvements

## Core Principles

- **Customer-first**: Prioritize customer value and usability
- **Iterative delivery**: Deliver small, testable increments
- **Clear ownership**: Each project has named roles and accountabilities
- **Data-informed decisions**: Measure impact and iterate based on evidence
- **Psychological safety**: Encourage feedback and learning

## Process Overview

### How OctoAcme Manages Projects

OctoAcme uses a structured, repeatable approach to project management that emphasizes:

- **Clear roles and responsibilities** — Project Managers coordinate delivery; Product Managers define outcomes; Developers build with quality; QA validates acceptance criteria
- **Lightweight artifacts** — Project One-pagers, backlogs, risk registers, and release plans keep teams aligned without unnecessary overhead
- **Regular communication** — Daily standups, weekly syncs, and milestone demos ensure transparency and early issue detection
- **Quality and testing** — Unit tests, integration tests, automated scanning, and manual QA ensure reliability before release
- **Risk management** — Proactive identification, escalation paths, and mitigation planning minimize surprises
- **Continuous improvement** — Retrospectives after each sprint and release capture learnings and drive iterative process improvements

### Communication Cadence

- **Daily**: Team standups (15 min) focused on progress, blockers, and dependencies
- **Twice weekly**: Delivery team syncs for detailed execution updates
- **Weekly**: PM + PdM alignment on roadmap and priorities
- **Monthly**: Stakeholder updates and broader communication
- **Ad-hoc**: Blocker escalation and incident response

## Key Checklists

Each process document includes a checklist to ensure you're following the OctoAcme approach:

- **Initiation Checklist**: One-pager, stakeholder alignment, decision gate
- **Planning Checklist**: Kickoff held, backlog prioritized, DoD documented
- **Execution Checklist**: Branching conventions, CI configured, regular demos
- **Deployment Checklist**: Acceptance criteria met, smoke tests, rollback plan
- **Retrospective**: What went well, improvements, action items with owners
